# 01 - 章介绍与讲解思路

第二章结束以后，咱们已经有了一套可以查询企业资料的知识库了。

但是，知识库只能帮助模型找到资料。

而如果用户想要执行一些具体的动作就不行了。

比如说，用户这么说：

> “查询订单 A1024 的状态。如果满足退款条件，就继续发起退款。”
>

这个时候只靠 `RAG` 就不行了。

因为大模型虽然可以理解为用户说的是什么意思。

但是！

它不能直接访问订单系统，更不能自己调用退款接口。

所以从这一章开始，咱们要解决一个新的问题，那就是：怎样让模型连接并使用真实的业务能力。

也就是讲 `MCP` 了。

这一章的内容，咱们会先从原生 `Tool Calling` 开始。

先看看 `Agent` 应用是怎样把工具交给模型，模型怎样返回工具调用请求，`Agent` 又怎样校验参数、执行函数，再把结果交回模型。

先把这个最小调用链跑通。

跑通了之后，再去讲 `MCP`。

然后陆陆续续的讲 `MCP` 中的 `Host`、`Client` 和 `Server`，完成 `Tools`、`Resources` 与 `Prompts`，跑通本地 `stdio` 和远程 `Streamable HTTP`，并了解授权、能力协商以及 `MCP` 的扩展能力。

最后在实现一个 `MCP` 的项目。

基本上这就是本章的讲解思路和内容了～～
